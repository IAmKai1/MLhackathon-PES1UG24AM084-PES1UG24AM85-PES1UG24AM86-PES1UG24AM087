The system runs on two laptops connected to the same network.

**Laptop 1 (model and API)** runs the FastAPI backend (api/app.py) with uvicorn on port 8000. At start-up it loads the tuned classifier (artifacts/final_model.joblib) and the decoder settings (artifacts/hmm_config.json), and serves the trips in the evaluation folder (data/evaluator_test). GET /trips returns the trip ids and observation counts. POST /predict with a trip id runs the complete pipeline from pathsnap/pipeline.py, the same code used in our experiments: projection, candidate generation, feature extraction, classification and Viterbi decoding. It returns the GPS points, the predicted route as polylines, the predicted arc for every observation, the evaluation metrics and the timing. Every request is logged on Laptop 1's console with the trip id, accuracy and processing time.

**Laptop 2 (user interface)** serves ui/index.html with Python's built-in web server. The evaluator enters Laptop 1's address, loads the ten trips, and selects one. The UI sends the trip id to the API, then draws the GPS observations and the predicted route on a map and shows the metrics. The map background uses keyless Esri tiles, with an automatic plain-background fallback, so the display never depends on a third-party key.

**Keeping ground truth on the server.** Features are built with the reference route hidden from the pipeline, so labels cannot leak into the model. The API reads the reference only after prediction, to compute accuracy, and returns only the resulting numbers, never the reference geometry. No predictions are hard-coded: every result is computed when the request arrives, as the API logs show. In our test run the UI on Laptop 2 (10.8.121.59) requested evaluator trip 15; the API processed 6,854 observations in about 5 s and returned an accuracy of 0.9255 (classifier only: 0.8385), identical to our offline evaluation.
