Each trip folder contains four header-less, whitespace-separated files. The .track file holds GPS observations (longitude, latitude, timestamp in seconds). The .nodes file holds road-network nodes (longitude, latitude), identified by their 0-based row index. The .arcs file holds directed road segments as pairs of node indices, with the row index serving as the arc id; a two-way street therefore appears as two arcs with identical geometry. The .route file lists, in travel order, the arc ids of the reference route. GPS rows do not correspond to rows of any other file; they must be related to the network spatially.

**Validity checks.** We searched every trip for non-finite values and non-increasing timestamps. No invalid rows and no out-of-order timestamps were found in any partition. The loader still drops non-finite rows and sorts by time, so the pipeline is safe on new data.

**Projection.** Longitude and latitude are angular coordinates, so Euclidean distance in degrees is not a physical distance: at the dataset's latitude (about 56 degrees north) one degree of longitude is only about 56% as long as one degree of latitude. We project every trip to metres with a local equirectangular projection centred on the trip's mean position. Each trip spans only a few kilometres, where the projection's distance error is far below GPS noise, and it avoids an external projection dependency. All distances in the pipeline (search radius, label cutoff, features and HMM transitions) are computed in this metric plane.

**Per-observation labels.** The route file is a sequence of arcs, not a label per GPS point. We assign each observation to a route arc with a monotone dynamic-programming alignment: it walks forward through the route, advancing at most 12 arcs per second, and minimises the total point-to-arc distance. Enforcing forward order prevents mistakes where the route passes close to itself, such as loops and U-turns.

**Trusted labels.** Where the GPS point lies more than 30 m from its aligned arc, the reference route most likely does not describe that moment of the trip, so we mark the label as untrusted. Untrusted observations are excluded from training and from every metric, but the model still predicts for them. This keeps 88.4% of training observations and 99.2% of student-testing observations.
