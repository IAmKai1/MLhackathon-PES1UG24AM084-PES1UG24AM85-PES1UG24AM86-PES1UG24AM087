We tuned HistGradientBoosting with Optuna's Tree-structured Parzen Estimator (TPE). Grid search would need an impractical number of evaluations for six continuous and integer hyperparameters, and random search ignores what earlier trials revealed. TPE models which regions of the search space produced good scores and concentrates new trials there, so it finds good configurations in far fewer evaluations.

Each trial was scored by 3-fold GroupKFold over the 80 training trips (groups = trips). Three folds instead of five kept 25 trials affordable; the grouping is what matters for avoiding leakage. Trial 0 was the untuned default configuration, so the tuned and untuned models are compared on identical folds. No student-testing or evaluator data was used in the search.

Tuning helped, but modestly. CV macro F1 rose from 0.9404 (trial 0) to 0.9418 (best, trial 22). On the student-testing trips, Top-1 accuracy rose from 0.9026 to 0.9076, macro F1 from 0.9386 to 0.9405 and log loss fell from 0.0715 to 0.0697, so every metric improved. All 25 trials lay between 0.9383 and 0.9418, which shows the default settings were already close to optimal for this feature set: the remaining errors come mostly from genuinely ambiguous observations (junctions and parallel roads), which no hyperparameter setting can resolve.

The improvement has a cost. The best configuration uses a lower learning rate (0.050), more and larger trees (600 iterations, 115 leaves) and only 44% of features per split, so training takes about 10 s instead of 1.3 s and inference is about five times slower (0.37 s vs 0.07 s for all student-testing candidates). Both remain well within the API's needs. The tuned model is saved as artifacts/final_model.joblib, and the full search record is in results/bayes_opt/optuna_trials.csv.
